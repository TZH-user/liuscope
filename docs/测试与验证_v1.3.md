# LiuScope v1.3.0 测试与验证报告

- **日期**：2026-10-28
- **验证对象**：LiuScope v1.3.0（master @ 本次 ESP32 支持 / Linux 适配 / 外观标准化批次）
- **方法学框架**：ISO/IEC/IEEE 29119（测试过程与文档口径）+ ISO/IEC 25010（质量特性）取形简化版——单人单机项目裁剪为「计划 → 分层执行 → 报告」，29119-3 的测试计划/报告要素覆盖：范围、条目、环境、层级、通过准则、结果与缺陷记录（本文件）。

## 1. 范围与条目

本轮变更（CHANGELOG [1.3.0] 全量）：
1. ESP32 连接层：DTR/RTS 中性打开、复位/下载模式线控、断线自动重连、VID/PID 标注、波特率预设
2. ESP32 日志层：IDF 日志解析着色、复位横幅装饰行、panic 高亮、backtrace 收集 + addr2line 对话框
3. Linux 适配：打开失败平台处置提示、设备屏更名「Linux 支持」（v2 M1/M2 并入主线）
4. 外观标准化：自定义主题（六键 + WCAG 复核警示）、页面显隐记忆

**不在本轮范围**：真机 ESP32 / 真机 Linux 板卡联调（待硬件到场）；Modbus/STM32/波形等存量功能回归中的真机部分（台架 COM9 用例归 H743 台架例行）。

## 3. L1 离屏回归（46 组）

新增组与关键断言：
- **ESP32 控制时序**：pulse_reset / enter_download_mode 的 dtr/rts 调用序列逐拍断言（esptool ClassicReset 语义），sleep 可注入
- **DTR/RTS 中性策略**：启用=两线松开、未启用=不动、线控不支持静默容错；经 `loop://` 全链验证打开后 dtr/rts=False
- **自动重连**：loop:// 底层口强制失效 → port_lost 一次 → 2s 重开成功 → reconnected，全程 stop 可打断
- **VID/PID**：6 组映射 + 未知/无 VID 不标注 + 下拉标注不破坏取口
- **IDF 日志**：等级着色映射、复位横幅装饰行（含 ANSI 样本与落显后缀）、panic 现场重置收集器、backtrace 只取 pc 列（pc:sp 交替口径）、开关旁路不收集
- **端口提示**：win32/linux × 权限/占用映射表
- **自定义主题**：改色即时生效 + ini 记忆 + 对比度不足上屏警示 + 恢复默认 + 跨重启保持
- **页面显隐**：开关 ↔ setTabVisible + ini 记忆

结果：**46/46 绿**（含既有 36 组零回归）。开发过程中抓到并修复的缺陷见 §6。

## 4. L2 打包产物冒烟

**过程记录（重要发现）**：首轮冒烟按 v1.2.1 经验以 90~240s 超时观察，多次「疑似挂起」；py-spy 三次采样栈位置各不相同（`test_connect_button_states → test_tx_alignment_and_hover → grab_span`），证实**并非挂起而是冻结模式逐像素断言极慢**（冻结渲染 + 全像素 Python 扫描）。处置：
1. 全量冒烟预算放宽到 25 分钟实测通过；
2. `qt/selftest.py` 加组级追踪（`SELFTEST_LOG` 环境变量）与 `--selftest-only=a,b` 子集开关（`qt/main.py`），供 CI 与本地定点诊断；
3. CI 冒烟步骤 timeout 8→30 分钟（`.github/workflows/ci.yml`）。

结果：完整冻结子集（42 组，剔除 headless/stm32_fake_cli/update_check）退出码 **0**（后台门禁运行，见下方结论行）；exe SHA-256：`98041e43abbea0aa0cba5ea027a66a54bbceab19aef1d1ced1c5d0ada29f9bae`。

## 5. L3 黑盒功能验证（对运行中的 exe）

`_verify/blackbox_v13.py`，通过 AI 通道对运行实例做黑盒断言（测试者不读源码，只见协议与界面）：
1. ping/help/status/settings_list 协议面完整
2. `settings_set theme=custom` 接受且 settings_get 回读一致（v1.3.0 新主题键）；dark 往返；非法 theme 拒绝
3. `settings_set port=loop://`（网络串口 URL 直通）；list_ports / 未连接 send 拒绝等错误路径健在
4. 截图证据：`_verify/evidence_v13/main_v13.png`（ESP32 线控按钮、Linux 支持 页签可见性）

结果：**11/11 PASS**（详见运行输出）。

## 6. 缺陷记录（本轮发现并修复）

| # | 缺陷 | 根因 | 修复 |
|---|---|---|---|
| D1 | 测试假端口构造器缺新关键字参数，自动连接路径静默失败 | SerialWorker 新增 dtr_rts_neutral/auto_reconnect 形参，FakeWorker 未同步 | 全部 FakeWorker 构造器与信号面同步 |
| D2 | 主窗顶行加 4 个线控按钮后最小宽度 1382px > 默认窗口 980px | 顶行弹性不足 | 线控按钮移至日志行右段（顶行 1134→不变，logbar 780→1040） |
| D3 | 「疑似冒烟挂起」 | 冻结模式逐像素断言极慢，超时设置过短；非缺陷 | 预算放宽 + SELFTEST_LOG 追踪 + 子集开关；CI timeout 8→30min |
| D4 | 测试断言 `isVisible` 在页签非前台时恒 False | Qt 可见性语义（祖先链） | 改用 isHidden 语义（显式隐藏状态） |

## 7. 质量特性自评（ISO 25010 口径，本轮相关项）

- **功能性**：新特性均有 L1 断言 + L3 黑盒覆盖；真机 DTR/RTS 时序留待硬件
- **可靠性**：自动重连有信号级测试；断线/占用/权限错误路径全部有用户可读提示
- **易用性**：ESP32 防复位默认关（保守）、IDF 解析默认开；自定义主题有对比度警示兜底
- **可维护性**：新逻辑集中在 core/esp32_control、esp_idf_log、port_hints + selftest_esp32_* 两个独立测试文件（groups() 契约）
- **可移植性**：Windows 主线；Linux 适配按需求度三档决策（docs/research/调研_Linux串口生态与适配决策.md）
